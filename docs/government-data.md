# 정부 직무정보를 먼저 쌓는 수집 설계

확인일: 2026-09-07. 정부 원문 데이터 → 사전 적재 DB → 검색·선택 → 사용자 실제 경험의 단계별 입력 → 개조식/서술식 작성.
사용자가 작성할 때 외부 API를 매번 호출하거나 AI로 정부 정보를 새로 만들지 않는다.

## 세 정보층을 구분한다

| 정보층 | 뜻 | 사용 원칙 |
| --- | --- | --- |
| 국가 직무능력 표준 | NCS 분류·능력단위·요소·수행준거·지식·기술·태도 | 코드와 버전으로 연결하되 각 API가 실제 제공한 필드만 사용 |
| 일반 직업정보 | 하는 일·업무수행능력·지식·교육훈련·관련직업 | 기관별 채용요건이 아닌 보조 자료로 표시 |
| 기관 채용 직무 | 특정 기관·연도·공고의 직무기술서 | 해당 공고의 원문을 우선하며 일반 NCS와 자동 동일시하지 않음 |

`job_profiles`는 기관 공고용으로 유지한다. 일반 NCS는 `occupation_catalog`에 별도 저장한다.
웹에서 참고정보를 선택해도 지원기관·기존 경험을 덮어쓰지 않는다.

## 수집·검색 명령

```bash
# 키 없이 받은 공식 파일을 개발용 DB에 적재
python -m jobandkill --db data/jobandkill.db catalog-import --format training-csv data/source-downloads/ncs-training-units-15083321-20251231.csv

# 승인키는 수집 서버 Secret의 JOBNKILL_NCS_SERVICE_KEY에만 설정
# 첫 호출 후 다음 실행은 중단 페이지부터 재개
python -m jobandkill catalog-sync --max-pages 100
# 새 전체 갱신 주기: 기존 데이터를 삭제하지 않고 첫 페이지부터 재검증
python -m jobandkill catalog-sync --restart --max-pages 100

# 원본 API 응답도 같은 정규화 경로로 가져오기 가능
python -m jobandkill catalog-import official-response.xml
python -m jobandkill coverage
```

공통정보 요청 주소는 공식 명세의 HTTPS `https://c.q-net.or.kr/openapi/NcsInfo/ncsinfodetail.do`로 고정한다.
JSON/XML 파서 테스트는 합성 fixture로 검증한다. 승인키로 성공응답을 받기 전에는 실 API 검증 완료라고 하지 않는다.
명세의 `totalCount=15540`은 예시이며 현재 실제 총수로 쓰지 않는다.

`catalog_sync_runs`와 `catalog_sync_pages`는 페이지 체크포인트와 실제 총수·고유키 수를 기록한다.
예산 소진·응답 실패·반복 페이지·누락은 완료와 구분한다. 총수와 고유키 수의 일치가 확인되어야 해당 API의 전체 순회를 완료로 기록한다.
CSV 가져오기는 그 파일의 스냅샷 범위만 의미하며 API 전체 수집으로 표시하지 않는다.
NCS 기준정보의 NCS006은 요소번호 요청값이 필요하므로, 7개 API가 있다는 이유만으로 모든 요소를 자동 열거할 수 있다고 단정하지 않는다.
주기 갱신은 정렬/버전 변경을 고려해 첫 페이지부터 새 실행을 만든다. 자동 재시도와 호출량은 제공자 승인 범위 내에서 제한한다.

| 상태 | 의미 | 조치 |
| --- | --- | --- |

| 권한 확인 필요/제한 | 공개되어 있어도 상용 이용권한 불명/제한 | 승인 확인, 대체 소스, 제외 |
| 수집 실패 | 요청·형식·할당량 등 실패 | 원인 해결 후 체크포인트부터 재개 |
| 문서 추출 실패 | PDF/HWPX/OCR 등이 아직 읽히지 않음 | 파서/검수 개선; 자료가 없다고 단정 금지 |
| 분류 연결 미확인 | 직업코드·NCS코드·기관직무 연결 근거 없음 | 검수 전 자동 동일시 금지 |
| 원문 미공개 | 게시기관이 원문을 제공하지 않은 것으로 확인 | 기관 공개자료 추가 확인·요청; AI 생성으로 대체 금지 |

현재 `coverage`는 등록 정보원, DB 수집상태, 첨부 권리/추출 상태를 보고한다.
정부 전체 기관/직무의 공식 모집단은 아직 확정하지 않았으므로 대한민국 전체 누락률(%)을 제공하지 않는다.
새 직업공통능력과 과거 직업기초능력 등 분류 개편은 버전별로 관리하며 특정 목록을 영구 고정하지 않는다.

## AI와 운영비

수집·DB검색·단계 입력·개조식/서술식 조합은 AI 호출 없이 작동한다.
추후 선택적인 문장 다듬기를 추가할 수 있으나 원문 출처나 사용자 경험·실적을 생성해 사실로 바꾸지 않는다.
모델 신규 학습이나 고객자료의 AI 전송은 이번 변경에 포함하지 않는다.

먼저 수집량·필드 충족도·검색 지연·문서처리 메모리를 측정한다. 이후 웹/수집 작업/문서저장소 용량을 산정한다.
이전 Render 금액은 데이터 실측 전 예시였으며 확정 운영견적이 아니다. 유료 자원 생성이나 아이비호스팅 변경은 하지 않았다.

## 배포 전 추가 검증

이번 검증에서 실제 CSV 적재, 13,400 offset의 마지막 42개 조회, 상세 원본 raw 비공개,
누락 훈련시간 38개 집계와 SQLite 무결성 검사를 통과했다.
로컬 Python 테스트 230개 실행에서 7개 환경 의존 검증을 건너뛰고 나머지 통과, Node 테스트 16개 통과.
공식 파일 원본·출처표시·개인정보가 없는 적재 DB는 `ncs-data-20251231.zip`으로 별도 보존했다.
브라우저 연결이 시간 초과되어 이번 턴 시각 QA는 미완료이다. HTTP·DOM 정적·단위검증을 시각 QA로 대체 보고하지 않는다.

스키마 버전은 10. 운영에서는 소유자 `init` 후 역할 ACL을 다시 적용해야 한다.
새 카탈로그 테이블은 web 읽기 전용, collector 쓰기, cleanup 접근 불가이다.
API키 성공응답, 운영 PostgreSQL 비슈퍼유저 검증, 전체 자료 범위 및 모바일 실기 QA를 마친 뒤 공개한다.
