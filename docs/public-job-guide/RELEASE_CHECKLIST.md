## A. 내용·데이터

- [ ] 제목·부제·대상 독자가 표지, 판권, README, Pages, EPUB/PDF metadata에서 동일하다.
- [ ] 기관 범위와 포함·제외 기준을 설명했다.
- [ ] “전국/전체/모든” 표현 옆에 데이터 채널, 기준일, 누락 가능성을 밝혔다.
- [ ] 현재 공고와 과거 사례가 명확히 구분된다.
- [ ] 공고 행의 기관명·공고명·접수기간·근무지역·고용형태를 원문과 대조했다.
- [ ] 필수 자격, 우대 자격, 가점, 제한경쟁을 분리했다.
- [ ] 지역인재 가점과 거주지 지원 제한을 분리했다.
- [ ] 편집 추론 필드에 `1차 분류/상세 확인 필요` 표시가 있다.
- [ ] URL 중복·깨짐·리디렉션과 공고 마감 상태를 검사했다.
- [ ] 출처 URL·확인일·데이터 기준일이 표와 데이터 파일에 남아 있다.
- [ ] 정정·삭제 요청 연락 경로가 있다.

## B. 윤문·편집

- [ ] 목차와 실제 제목·페이지/링크가 일치한다.
- [ ] 용어집 기준으로 기관 유형, 채용형태, 전형 용어를 통일했다.
- [ ] 숫자·날짜·단위·띄어쓰기·영문 약어 스타일이 일관된다.
- [ ] 같은 내용의 중복 장·표·문단을 제거했다.
- [ ] 단정, 과장, 합격 보장, 확인되지 않은 컷·배수·질문을 제거했다.
- [ ] 모든 표·그림에 번호, 제목, 출처, 기준일이 있다.
- [ ] 최종 교정자가 EPUB·PDF에서 각각 오탈자를 표본 확인했다.

## C. 접근성·디자인

- [ ] H1-H2-H3 제목 계층이 논리적이다.
- [ ] 모든 정보 이미지에 유용한 alt가 있고 장식 이미지는 빈 alt이다.
- [ ] 표 헤더가 명확하고 넓은 표에 본문 요약이 있다.
- [ ] 색 없이도 상태·범례·중요도를 구분할 수 있다.
- [ ] 본문·링크·버튼의 대비와 키보드 포커스를 확인했다.
- [ ] EPUB 글자 확대와 모바일 화면에서 가로 스크롤 문제를 점검했다.
- [ ] PDF에서 한글 누락 없이 텍스트 검색·복사가 된다.
- [ ] 표지와 OG 이미지가 최종 승인본이며 권리 정보가 기록됐다.

## D. 권리·메타데이터

- [ ] 저작권자·발행인·저자/편집자 표기를 확정했다.
- [ ] 콘텐츠와 코드 라이선스를 확정하고 실제 LICENSE 파일을 넣었다.
- [ ] `THIRD_PARTY_NOTICES.md`에 이미지·폰트·데이터·인용 자료를 기록했다.
- [ ] 공공데이터·공고문·기관 로고의 원 이용 조건을 확인했다.
- [ ] 개인정보·민감정보·비공개 자료가 없음을 확인했다.
- [ ] ISBN/유통 식별자가 필요한 판매 채널이면 발급·반영했다.
- [ ] UUID, 언어, 발행일, 수정일, 판, 버전이 EPUB/PDF/웹에서 동일하다.
- [ ] 면책과 최신 공고 확인 안내가 눈에 잘 띈다.

## E. 자동 빌드

- [ ] `./scripts/build.sh`가 깨끗한 환경에서 성공한다.
- [ ] 같은 빌드에서 EPUB·PDF·HTML·Pages 파일이 생성된다.
- [ ] `dist/epub-validation.txt`, `dist/pdf-info.txt`, `dist/SHA256SUMS` 검증이 성공한다.
- [ ] EPUBCheck 오류가 0건이다.
- [ ] PDF가 열리고 `pdfinfo`가 정상이다.
- [ ] EPUB·PDF·HTML이 같은 원고 commit에서 생성됐다.
- [ ] `SHA256SUMS.txt` 검증이 성공한다.
- [ ] 빌드 산출물에 내부 경로·토큰·개인정보가 노출되지 않는다.

## F. GitHub Pages

- [ ] Settings → Pages의 Source가 GitHub Actions다.
- [ ] `SITE_URL`을 실제 주소로 설정했거나 기본 Pages 주소가 정확하다.
- [ ] `github-pages` environment의 배포 보호 규칙을 확인했다.
- [ ] 기본 브랜치 보호와 필수 Actions check를 설정했다.
- [ ] 랜딩 페이지, 본문 HTML, EPUB/PDF, 체크섬 링크가 모두 200 응답이다.
- [ ] canonical, `og:url`, `og:image`, JSON-LD URL이 실제 주소와 일치한다.
- [ ] `robots.txt`와 `sitemap.xml`이 열리고 최종 URL을 가리킨다.
- [ ] 모바일과 데스크톱에서 표지·버튼·본문을 검수했다.
- [ ] 사용자 지정 도메인이 있으면 DNS와 HTTPS를 확인했다.

## G. GitHub Release

- [ ] 버전 정책에 맞는 태그 이름을 정했다.
- [ ] `CHANGELOG.md`와 Release notes에 데이터 기준일·핵심 변경·정정을 기록했다.
- [ ] 최종 승인 후에만 서명된/보호된 commit에 태그를 만들었다.
- [ ] Release에 EPUB, PDF, HTML, `SHA256SUMS.txt`가 첨부됐다.
- [ ] 자산 파일명과 책 버전이 일치한다.
- [ ] Release 페이지에서 내려받은 파일로 체크섬을 다시 확인했다.
- [ ] 필요 시 이전 판을 유지하고 정정판의 관계를 명시했다.

## H. 배포 후 24시간

- [ ] Pages와 Release 다운로드를 로그아웃 상태에서 재확인했다.
- [ ] 주요 공유 채널에서 OG 카드 제목·설명·이미지를 확인했다.
- [ ] 전자책 리더 2종 이상에서 EPUB을 열어 목차·표·이미지를 확인했다.
- [ ] 데스크톱·모바일 PDF 뷰어에서 링크와 글꼴을 확인했다.
- [ ] 발견된 문제를 Issue로 기록하고 심각도·담당·수정 버전을 지정했다.
- [ ] 승인자·배포 시각·Actions 실행 URL·체크섬을 릴리스 기록에 남겼다.
